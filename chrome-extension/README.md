# 正方教务 · 通用选课助手（Chrome 扩展）

Manifest V3 的 Chrome 扩展。**登录教务系统后，只要你人在正方教务的页面上（不在选课页），扩展会先把你送到「自主选课」页面**，到了之后右下角自动出现抢课面板。

**抢课途中如果登录态掉了，扩展会自动用你存好的账号密码重新登录，跳回选课页，接着从刚才断掉的目标继续抢。**

**课程列表是直接调用查询接口拿的 —— 不需要点页面上的「查询」按钮。** 按钮被浮层遮住、在手机视口外、或者页面脚本压根没跑起来，都照样能查。

**（v2.5.0）** 还能按 **星期 / 节次 / 周次** 精确挑教学班、**定时开抢**、**换课**，
以及在冲突时**自动退掉可退的通识选修课**（默认关闭，必修永不自动退）。

> 匹配规则是 `*://*/xsxk/*` + `*://*/xtgl/*` —— 不绑学校、不绑课程、不绑轮次。
> 前者是选课模块，后者是主菜单/首页（登录成功后落地的那一页），一处都少不了。

## 安装

Chrome 出于安全不允许安装未上架的 `.crx`，只能「加载已解压的扩展程序」。**只需做一次**：

1. 地址栏打开 `chrome://extensions`
2. 打开右上角的 **开发者模式**
3. 点 **加载已解压的扩展程序**
4. 选择本文件夹（`chrome-extension`，里面有 `manifest.json` 的那一层）
5. 装好后建议把它**固定到工具栏**（拼图图标 → 图钉）

装完去教务系统登录一下，你应该会被自动送到「自主选课」页面，面板随之出现。

> 以后我改了代码，你只要回 `chrome://extensions` 点一下这个扩展卡片上的 **↻ 重新加载**，再刷新页面即可，不用重新添加。

**扩展 ID：`dbmnknondalhkjdciheojjdlkcaobfpf`**

（ID 由 `manifest.json` 里的 `key` 决定，已经写死了，所以同一份代码不管怎么装、装在哪台机器，ID 都不变。）

## 已经打好的包（`../dist/`）

> ⚠️ **本仓库不含 `dist/` 目录。**
> `zf-xk-helper.pem` 是 RSA 私钥（它决定了上面的扩展 ID），`.crx` / `.zip` 属于构建产物，
> 三类都已被 `.gitignore` 排除、不随仓库分发。
> 需要的话在本地跑一次 `cd tools && node pack-crx.mjs` 即可生成（首次会自动造一对新密钥）。

下表描述的是**本地打包后**会得到的三个文件：

| 文件 | 说明 |
|------|------|
| `zf-xk-helper-2.5.0.crx` | CRX3 格式，已用 RSA-2048 签名 |
| `zf-xk-helper-2.5.0.zip` | 同样的内容，纯 ZIP |
| `zf-xk-helper.pem` | **私钥，请勿外传**。它定义了扩展 ID，丢了下次打包就会变成另一个 ID |

### ⚠️ 关于 `.crx` 的安装现实

Chrome 从很早就**禁止安装非 Chrome 网上应用店来源的扩展**（Windows / macOS 稳定版）。
把自己签名的 `.crx` 拖进 `chrome://extensions`，通常会被拒，报错码是
`CRX_REQUIRED_PROOF_MISSING` —— 因为我们没有网上应用店的那层签名背书。

所以：

- **你自己用 → 别用 .crx**，用最上面那套「加载已解压的扩展程序」，或者用 `.zip` 解压后再加载。这条路一定通。
- **`.crx` 适合这些场景**：
  - Chrome for Linux（开发者模式下仍允许拖入 `.crx`）
  - 上传到 Chrome 网上应用店（商店会重新签名，然后正常分发）
  - 企业环境用策略批量推送
- **想发给同学**：给 `.zip`。对方解压后 → `chrome://extensions` → 开发者模式 → 加载已解压的扩展程序。
  （`.crx` 本身其实也就是「12 字节 + protobuf 头 + ZIP」，改名成 `.zip` 同样能解压，但不建议这么绕。）

### 重新打包

改了代码之后：

```bash
cd chrome-extension/tools
node pack-crx.mjs
```

脚本会复用 `dist/zf-xk-helper.pem`（所以 ID 不变），重新生成 `.crx` 和 `.zip`，
并**自检**：魔数、CRX 版本、RSA 签名验签、内嵌 ZIP 起始签名。全部通过才会退出码 0。

包内只含 Chrome 真正需要的 **9 个文件**（`manifest.json` / `background.js` / `rsa-pkcs1.js` /
`content.js` / `popup.html` / `popup.js` / 三个图标）。`tools/` 和 `README.md` 都已排除 ——
所以改文档不需要重新打包。

打包细节（不依赖任何三方库）：ZIP 用 `zlib.deflateRawSync` 手写，
CRX3 头用 protobuf 手写（`CrxFileHeader.sha256_with_rsa` + `signed_header_data`），
签名内容是 `"CRX3 SignedData\0" + u32le(len) + signed_header_data + zip`，用 `node:crypto` 签。

## 不用点「查询」按钮也能查课（v2.4.0 新增）

正方教务的「自主选课」页要先点一下「**查询**」才会显示可选课程。
如果这个按钮**点不到**（被浮层压住、在手机小视口外、页面脚本出错导致按钮没反应），
人就卡在第一步，课也就抢不到了。

**扩展从设计上就不依赖这个按钮**：它做的正是「查询」按钮背后那件事 ——
直接 `POST` 课程列表接口 `zzxkyzb_cxZzxkYzbPartDisplay.html?gnmkdm=N253512`，
自己带参数、自己解析 JSON。整个过程一次 DOM 事件都不派发，自然也谈不上「按钮点不到」。

### 但这里藏着一个很阴的坑（v2.4.0 修掉）

光「不点按钮」还不够。实测发现：**那个页面的 44 个查询参数里，有 29 个在服务器返回的 HTML 里根本不存在**，
它们是页面自己的 JS 在运行时造出来的。参数一旦缺失，服务端的反应非常不利于排查：

| 缺失的参数 | 服务端反应 |
|---|---|
| `kklxdm` | `{"flag":"1","tmpList":[]}` ← **HTTP 200、不报错、0 门课** |
| `bklx_id` | 同上 —— **静默 0 门课** |
| `xkkz_xh` | `{"flag":"0","msg":"加密串错误…"}` ← 这个至少会报错 |
| `rwlx` | 反而返回 63 门（超集，无害） |

也就是说：**页面脚本一旦没跑完（手机上浏览器禁用同步 XHR 会让整段 JS 直接抛错），
扩展就会拿到「0 门课」的假结果**，面板显示「本轮列表里没有匹配的课程」——
看起来就像学校没放课，实际上是参数没就绪。这大概就是手机上抢不到课的真实原因。

### 三层补救（全程不需要人工点任何东西）

| 层 | 做什么 | 依据 |
|---|---|---|
| ① `first*` 回落 | 正式字段是空的就改读服务器渲染的 `firstKklxdm` / `firstXkkzId` / `firstXkkzXh` / `firstNjdmId` / `firstZyhId` | 实测这两组值**完全等价** |
| ② 服务器自补 | 自己 `fetch` 一次当前页的**原始 HTML** 抠 `first*`，再 `POST zzxkyzb_cxZzxkYzbDisplay.html` 拉那个 HTML 片段，抠出 `bklx_id` / `rwlx` / `xklc` 等**只有页面 JS 才有的值** | `bklx_id` 在 Index 页里完全没有，只在这个片段里 |
| ③ 兜底触发 | 最后一招才是用 `btn.click()` 程序化点一次页面自己的「查询」按钮 | 内容脚本在隔离世界读不到页面的 jQuery，但 **DOM 是共享的**，原生 `click()` 派发的事件页面收得到 |

补到的值会记在日志里（标为 `server`），`__XK_HELPER__.params()` 可以随时查看每个参数的值与来源。

### 不再「静默 0 门课」

查询前后都会做一次**关键参数体检**：

- 参数没就绪 → **先补齐再查**，并说明补了什么；
- 补齐后仍缺 → 明确说「查询参数缺失（xxx）：本页脚本没正常初始化」，**而不是说「没有匹配的课程」**；
- 查回来是 0 门 → 再体检一次，确认是「真的没课」还是「参数不对」。

面板里的「自检（只读）」也会把参数体检结果打出来，例如：

```
✔ 查询参数就绪：kklxdm(dom)  bklx_id(server)  xkkz_xh(firstXkkzXh)
  来源 dom=页面字段 / server=扩展自补 / first* =服务器默认值字段
✔ 课程列表可读（直连接口，未使用页面按钮）：本页 4 门（篮球、武术、体育游戏、羽毛球…）
```

> 手机上真遇到查不到课时，看这行就知道是「参数没就绪」还是「登录态没了」还是「真的没课」。

## 退选 · 换课 · 冲突重选（v2.5.0 新增）

参考了两个开源的正方抢课实现（[ThisIsLittleSky/grabber](https://github.com/ThisIsLittleSky/grabber)、
[ceilf6/Auto_courseGrabber](https://github.com/ceilf6/Auto_courseGrabber)），把它们的几套逻辑搬了进来。

### 退选接口

```
POST /xsxk/zzxkyzb_tuikBcZzxkYzb.html
kch_id + jxb_ids(=do_jxb_id) + xkxnm + xkxqm + txbsfrl=0
```

返回字符串 `1` 才是退成功。退选和提交一样，**用的是那个 256 位加密串 `do_jxb_id`，不是 `jxb_id`**。

### 安全铁律（这一段是整套逻辑的地基，别改）

> **只退「可退的选修课」——`kklxdm === '10'` 且 `rwlx === '2'`。其余一律只告警、不动手。**

判据就写在 `isDroppable()` 里。必修、专业课、任何字段对不上的课，**永远不会被自动退掉**。
另外：

- 整个功能挂在 `OPTS.autoDrop` 上，**默认 `false`**。你不显式打开，它一次都不会退课。
- 退选前先跑一遍 `查已选列表 → 本地算时间重叠 → 才决定退谁`，任一步不确定就放弃并告警。
- 「退选不可逆」——所以打开前请先在**演练模式**下看一遍日志，确认它挑中的是你要退的那门。

### 冲突自动重选

提交被服务端拒、且文案里有「冲突」时：

```
1. 解析目标课的 sksj → {星期, 节次, 周次}
2. 拉已选列表，逐门用同一套解析算 schedulesOverlap
3. 重叠的课里筛出「可退选修课」→ 退掉 → 重新查教学班 → 重提
4. 重叠的只有必修 / 定位不到 / 退选失败 → 只告警，停在这一轮
```

**冲突判定在服务端做**，本地这套只是用来「定位该退哪门」，不是替代服务端。

### 换课（骑驴找马）

在目标卡片的 ⚙ 里填「**替换课程号**」= 你的保底课课程号。之后：

> 目标课确认**有名额**了 → 才去退保底课 → 再提交目标课。

只在「已经确认目标课有名额」之后才动保底课，是为了把「退了保底却没抢到」的窗口压到最小。
但**这个风险依然存在**（保底课退掉的瞬间可能被别人抢走），请自行权衡。同样受 `autoDrop` 开关管制。

### 上课时间结构化解析

把正方那个压扁的字符串拆成能算的结构：

```
'星期一第1-2节{1-16周}<br>星期三第5-6节{3-8周}'
        ↓ parseSchedule()
[{day:1, start:1, end:2, weeks:{1..16}}, {day:3, start:5, end:6, weeks:{3..8}}]
```

周次支持 `1-16` / `1-16(单)` / `2-16(双)` / `1-16(1-16)` 四种写法。有了它才能：

- **精细筛选**：目标卡片可填 只选/排除 **星期、节次、周次**（比原来的模糊 indexOf 准得多）
- **本地预判冲突**：勾「本地避开与已选课时间冲突的教学班」，选班时先用本地课表筛一遍，
  省掉一次服务端往返。**如果全都冲突就照旧挑一个** —— 让服务端给最终判定，不自己把路堵死。
- **冲突源定位**：上面「冲突自动重选」用的就是它

> ⚠ 一个刻意的宽容设计：**sksj 解析不出来时不拦**（直接放行）。
> 不同学校的格式有差异，认不出来就把整批课挡光，比不筛更糟。

### 定时开抢

面板「运行参数」里填个时刻（留空 = 立即开始）。到点之前**只倒数、一个请求都不发** ——
早发请求只是在替别人热身。

### 冷却 · 熔断 · 提示音

| 机制 | 默认 | 说明 |
|------|------|------|
| 失败冷却 | 6000 ms | 某个目标提交被拒后，**只**让这个目标歇一会儿；别的目标照跑 |
| 连败暂停 | 关（0） | 所有目标都连续失败 N 轮就自动停下来，防把账号打异常。日志会给处置建议 |
| 提示音 | 开 | 抢到 880Hz 短音、被拒/熔断 330Hz 长音。用 WebAudio 现场合成，**不需要任何权限**，也不加载任何文件 |
| 重入互斥 | — | 轮询和「预览/执行一轮」不会同时打同一个接口 |

## 自动跳到选课页（v2.2.0 新增）

**每次加载页面，第一件事都是判断「我在不在自主选课页」。**

| 判定结果 | 会做什么 |
|---|---|
| 已在自主选课页 | 正常挂出抢课面板 |
| 在正方教务的其它页（主菜单 `/xtgl/index_initMenu.html` 等） | 按设置跳转到自主选课页 |
| 在登录页 / 别的网站 | **什么都不做**，绝不乱跳 |

判定靠三样东西，任一命中即可：页面隐藏域 `xkkz_id` + `xklc` + `kklxdm` 齐全、
URL 含 `zzxkyzb_cxZzxkYzbIndex.html`、或页面里能定位到「自主选课」菜单项。

### 三种跳转模式（面板里可切换）

| 模式 | 行为 |
|---|---|
| **自动跳转**（默认） | 落地主菜单就立刻被送到选课页，你什么都不用点 |
| **弹提示询问** | 右下角弹一条小提示，「前往选课」/「取消」由你点 |
| **不处理** | 完全不干预，需要你手动点菜单 |

选课页的地址不是硬编码的：先从页面上的「自主选课」菜单项里把真实路径抠出来，
抠不到才回落到 `/xsxk/zzxkyzb_cxZzxkYzbIndex.html?gnmkdm=N253512&layout=default`。

### 三道防死循环的闸

自动跳转最怕跳进死循环（比如登录态失效：跳过去 → 被弹回登录页 → 又满足跳转条件 → 再跳）。
所以有三道闸，任一命中就不跳：

1. **返回导航不跳** —— 你是按浏览器「后退」回来的，说明不想被送走，那就别送。
2. **一分钟内最多跳 2 次** —— 超过就静默，避免页面之间反复弹。
3. **点过「取消」后 5 分钟不再提示** —— 尊重你刚才说不。

另外登录页本身是认不出来的（有密码框即判为登录页），所以**登录前不会跳**——
这也是防死循环最根本的一条。

> 如果你把跳转设成了「不处理」或「弹提示询问」，也可以随时点工具栏图标，
> 弹窗里会给一个「带我去选课页」的按钮。

## 账号 · 掉线自动重登（v2.3.0 新增）

抢课最怕的不是抢不到，是**抢到一半登录态掉了**：页面还在，请求却全被弹回登录页，
你人不在电脑前，等发现时轮次已经结束了。

所以面板里多了一块「**账号 · 掉线自动重登**」：

```
账号   [2026000001        ]
密码   [••••••••••]  👁
[✓] 记住密码（关掉浏览器就清掉）
[✓] 掉线时自动重新登录
[ 保存并登录 ]   [ 清除 ]
```

### 掉线是怎么被发现的

三个信号，任一命中就判定掉线：

| 信号 | 说明 |
|---|---|
| 请求被 **302 到 `login_slogin.html`** | 会话过期的典型表现 |
| 响应体**本身是登录页 HTML** | 更隐蔽的一种：接口回 HTTP 200，但内容是一整个登录页 |
| 列表接口返回 **`flag=0` 且文案含「登录 / 会话 / 失效 / 超时 / 非法」** | 用 `checkSession()` 复核一次，确认了才算 |

复核这一步很重要：正方偶尔会因为别的原因回 `0`，**不复核就直接重登，会把本来好的会话踢掉**。
所以只有「确认真的掉线」才会触发重登。

### 自动重登只在自己人掉线时才发生

它**绝不会无缘无故替你登录**。触发条件是同时满足：

1. 面板里的「掉线时自动重新登录」还勾着；
2. 账号密码都填了；
3. 最近 10 分钟内登录失败**不到 3 次**；
4. 存在一个有效期 5 分钟的 `zxh-relogin` 标记 —— 这个标记**只有扩展自己在检测到掉线时才会写**。

第 4 条是关键：你如果自己手动打开登录页，扩展不会去抢着登录。

流程是 `检测到掉线 → 打标记 → 跳到登录页 → 自动填表提交 → 成功后跳回选课页 → 自动续抢`。

### 关于失败与锁定

**失败之后绝不自动重试**，这是刻意的：

> 密码错了还反复自动重试，是最容易把学号送进「账号已锁定」的做法。
> 所以一次失败就停手，在面板里用红字把服务端的原文告诉你（例如
> 「用户名或密码不正确，请重新输入！」），由你决定要不要改密码再试。

连续失败计数有 10 分钟的自动作废时间，不会累积成永久封禁。

### 密码存在哪 —— 以及为什么不是 localStorage

| | 存在哪 | 页面 JS 能读到吗 | 关掉浏览器 |
|---|---|---|---|
| **默认** | `chrome.storage.session` | **不能** | 自动清空 |
| 勾了「记住密码」 | `chrome.storage.local` | 不能 | 保留 |

默认走 **`chrome.storage.session`**：它是**内存态**的，页面自己的 JS 拿不到，
关掉浏览器就没了 —— 你这次抢课期间它是活的，抢完随手关浏览器它就不留痕迹。

> 技术上有个小坑：MV3 里 `storage.session` 默认**只对扩展自己的页面（弹窗、后台）开放**，
> 内容脚本读不到。所以要靠后台脚本 `background.js` 调一次
> `chrome.storage.session.setAccessLevel({ accessLevel: 'TRUSTED_AND_UNTRUSTED_CONTEXTS' })` 把它放开。
> `background.js` 存在的**唯一理由**就是这个 —— 它不发任何网络请求。

**导出的配置 JSON 里永远不含密码**（只有 `opts` + `targets`），所以把配置发给同学也不会泄露账号。

面板里的密码框在**未加载完成时是空的**，即使勾了「记住密码」，存储里的密码也只在需要登录时才被读出来用。

### 密码在网络上是怎么传的

正方教务的登录接口要求密码用 **RSAES-PKCS1-v1_5** 加密后再 base64（`mmsfjm !== '0'` 时）。
但浏览器的 **WebCrypto 只提供 RSA-OAEP，不提供 PKCS#1 v1.5** —— 这是规范层面的限制，绕不过去。

所以 `rsa-pkcs1.js` 是一份**手写的、零依赖的纯 JS RSA 实现**：

- 大数用 **16 位分肢（base 65536）的 `Uint16Array`** 表示，小端序 —— 乘积一定小于 2³²，不需要 BigInt；
- 模幂、取模（逐位长除法）、字节/base64/UTF-8 编解码全部手写；
- 只做一次加密（登录时），实测 **约 25ms**，不影响体验。

它的正确性由 `tools/test-rsa.mjs` 的 **47 条断言**保证：与我方加密 → Node 的 OpenSSL 私钥解密做**往返比对**，
并把大数运算结果与 `BigInt` 逐条对照，覆盖 2048/1024 位密钥、中文与 emoji、1 字节到 245 字节的边界长度、
前导零模数、随机填充等。

整条登录链路则由 `tools/test-login-flow.mjs` 的 **30 条断言**端到端验证 ——
用假 `fetch` 扮演正方服务器，**最关键的一条是：脚本真正 POST 出去的 `mm`，用 Node 的私钥能解回原密码**。

> ⚠️ 前置条件：如果你学校的登录页**带验证码**，自动重登会**直接放弃**并在面板里说明原因
> （不白试一次、不浪费你的失败次数）。这种情况只能手动登录。

## 使用

```
1. 登录教务系统（人会自动被送到「选课 → 自主选课」）
2. 右下角面板 →「账号 · 掉线自动重登」：填账号密码、勾上「掉线时自动重新登录」← 想让它兜底就做这步
3. 右下角面板：「＋ 添加目标」→ 填课程名关键词（如 篮球）
```

- **第 2 步是可选的**，但强烈建议做：不做的话掉线就得你自己发现、自己重登，抢课会停在半路。
- **「仅演练」默认勾着**，而且演练模式下匹配到目标会**立刻自动停**并提示，手滑也不会提交。
- 多目标按**从上往下**的顺序依次尝试：第一个抢不到自动试第二个，抢到就标记完成、继续下一个。
- 「已选过的课程自动跳过」默认开启：提交前会拉一次已选名单，已经在里面的课程直接跳过。
- 目标高级选项（点卡片上的 ⚙）：课程号、只选/排除教师、时间要求、**只选/排除星期·节次·周次**、
  最少剩余、**本地避开冲突**、**替换课程号（换课）**。
- 想掐点开抢：在「运行参数」里填「定时开抢」，到点才开始发请求，期间只显示倒计时。
- 抢到 / 目标全部完成会**自动停止**，也能随时手动停。
- 配置存在扩展自己的存储里，面板里可「导出 / 导入 JSON」。「替换课程号」这类新字段也在导出里。

### 点「自检（只读）」可以随时体检

在面板「配置」里。它会跑三个只读检查：
1. 能不能读到页面隐藏域（轮次 / 类别 / 学年学期）
2. 课程列表接口通不通
3. 已选列表接口通不通

三行都是 ✔ 就说明一切正常。面板一加载也会自动跑一次课程列表探测，结果显示在日志区。

## 权限：只有 `storage`

安装时不会有「读取您在所有网站上的数据」这类吓人的提示。

- `storage` —— 存你的目标队列和运行参数（以及可选的账号密码），不碰网站的 localStorage。
- 只有 `storage` 一项权限，**没有 `host_permissions`、没有 `tabs`、没有 `cookies`**。
- 那个 `background.js`（service worker）**不发任何网络请求**，它只做一件事：
  把 `storage.session` 的读取权限开放给内容脚本。所有教务系统请求都在内容脚本里发。
- 内容脚本的 `matches` 只有两条：`*://*/xsxk/*` 和 `*://*/xtgl/*`，
  Chrome 只会把它注入正方教务这两个路径下的页面，其他网站完全不碰。
- 面板自己带一个启动闸门：先判断当前页面是不是选课页。
  不在选课页就**不会注入面板**，只会按设置跳转或安静退出。
- 跳转目标是从页面上现抠的，不写死 URL；且带三重防循环闸（见上文）。

## 它是怎么工作的（几个刻意的设计决定）

### 用内容脚本，不用 service worker 发请求

面板所有请求都是**同源请求**（相对路径 `/xsxk/...`），在内容脚本里发出去，自动带上你已登录的 `JSESSIONID`。

**千万不要把这些请求挪到 background service worker 里做** —— 那样请求的发起方变成扩展源，对教务系统就是**跨站**请求，`SameSite=Lax` 的会话 Cookie 不会被带上，必然失败。

### 跑在隔离世界（isolated world）

内容和页面共享同一个 DOM（所以能读隐藏域、能插面板），但 JS 环境是独立的。这带来一个**很实在的好处**：

> 正方教务**全站**覆盖了 `Array.prototype.filter` 和 `.some`，把它们实现成回调参数顺序反过来的版本 ——
> `arr.filter(x => x.xxx)` 会**静默返回空数组**，不报错、不抛异常。
>
> 隔离世界的原型是干净的，这个坑影响不到扩展。

（代码里仍保留了自实现的 `where()` 作为防御，万一以后改成主世界注入也不会烂。）

### 提交参数里的 `do_jxb_id`

正式选课接口的 `jxb_ids` 必须是服务端每次动态下发的加密串 `do_jxb_id`，**不是** `jxb_id`；
传错服务端会回「出现未知异常，请与管理员联系！」。扩展会自动取用并校验令牌有效性，偶尔服务端下发无效令牌时会重试一轮。

## 和 Tampermonkey 版的区别

|  | Chrome 扩展（本目录） | UserScript（`zf-xk-helper.user.js`） |
|---|---|---|
| 安装 | 加载已解压扩展，一次到位 | 需先装 Tampermonkey |
| **自动跳到选课页** | **有**（v2.2.0 起） | 无 |
| **掉线自动重登并续抢** | **有**（v2.3.0 起） | 无 |
| **不点「查询」按钮也能查课** | **有**（v2.4.0 起） | 无 |
| **星期/节次/周次筛选 · 定时开抢 · 换课** | **有**（v2.5.0 起） | 无 |
| **冲突时自动退可退选修课** | **有，默认关闭**（v2.5.0 起） | 无 |
| 密码存储 | `chrome.storage.session`（内存态，页面 JS 读不到） | 页面 `localStorage`（同源可读） |
| 运行环境 | 隔离世界（不受站点原型污染） | 主世界 |
| 配置存储 | `chrome.storage.local` | 页面 `localStorage` |
| 控制台 API | 要先把 DevTools 控制台的执行环境切到「选课助手」这个上下文 | 直接在页面控制台可用 |
| 弹出面板 | 有工具栏弹窗，可查看状态 / 折叠面板 / 手动跳转 | 无 |

> 两边的**抢课本体**（直连接口查列表 / 展开教学班 / 拿 `do_jxb_id` / 提交）逻辑一致，
> 但上面那几行新能力目前在 UserScript 版里都还没有。想用全套就用扩展版。

> 上面提到的控制台差异：因为隔离世界和页面主世界是两个 JS 环境，
> 页面控制台里直接敲 `__XK_HELPER__` 会是 `undefined`。
> 要在 DevTools 的 Console 左上角把 **JavaScript context** 下拉框切到本扩展的名字，就能用了。

## 故障排查

| 现象 | 原因 / 处理 |
|------|------|
| 选课页没出现面板 | ① 装了扩展后**没刷新页面**；② 回 `chrome://extensions` 看扩展有没有报错；③ 确认页面在 `/xsxk/` 或 `/xtgl/` 下 |
| 在主菜单被自动跳转，但我不想要 | 面板里的「不在选课页时」改成 **不处理** 或 **弹提示询问**。改成不处理后再也不用面板时，工具栏弹窗里也能手动过去 |
| 跳转提示弹了又弹 / 页面来回跳 | 已经被防循环闸拦下了，正常最多一分钟 2 次。若确实卡住，检查是不是登录态失效了（重新登录即可） |
| 按浏览器「后退」后又被弹回选课页 | 不会发生 —— 返回导航是一道明确的闸，不跳 |
| 面板出现，但日志写「接口探测失败：返回 0」 | 登录态问题。若已配好账号，扩展会自己重登；否则刷新页面或重新登录 |
| **页面上的「查询」按钮点不到 / 在手机上按不动** | **不用管它**。扩展直接调查询接口，不走按钮。只要面板的「自检」里课程列表那一行是 ✔ 就正常 |
| 日志写「查询参数缺失（kklxdm 等）」 | 本页脚本没跑完（手机浏览器常见）。扩展已尝试自动补；仍失败就**用电脑版 Chrome 刷新一次选课页** |
| 日志写「课程列表可读：本页 0 门」，但你知道有课 | 0 门有两种可能，日志会区分：参数没就绪（会说缺哪个）vs 真的没有。先看自检的参数体检行 |
| 掉线了但没自动重登 | ① 面板里「掉线时自动重新登录」没勾；② 账号密码没填全；③ 10 分钟内已失败 3 次（等一会儿）；④ 登录页带验证码（面板会写明） |
| 自动重登失败，红字写「用户名或密码不正确」 | 密码存错了或改过。改密码后点「保存并登录」重试。**不要连续硬试**，会触发账号锁定 |
| 不想让扩展存密码 | 面板里点「清除」；或干脆不勾「记住密码」—— 默认就是只存内存、关浏览器即清 |
| 「预览匹配」显示"没有符合筛选条件的教学班" | 该课程的教学班都不满足你的筛选（常见原因：`最少剩余` 默认 1，而班级已满）。想看看全部教学班就把「最少剩余」改成 0 |
| 「本轮列表里没有匹配的课程」 | 课程名关键词没匹配上，或这门课不在当前轮次/当前类别里。先不填任何高级条件、只留课程名的头两个字试试 |
| 填了「只选周次/节次」结果一门都不匹配 | 你的 sksj 写法可能不是标准格式（`星期一第1-2节{1-16周}`）。用 `__XK_HELPER__.parseSchedule('原文')` 看能不能解析出来；解析不出时筛选会自动放行，所以"全不匹配"更可能是条件本身写太严 |
| 日志写「冲突处理：重叠的是必修/不可退课」 | 按安全规则不动手。要么自己手动退，要么换一门不冲突的教学班（可用「排除节次」避开） |
| 开了自动退选但一门都没退 | 三条门槛都要过：① 服务端明确说「冲突」；② 本地能定位到时间重叠的课；③ 那门课得是 `kklxdm=10 且 rwlx=2`。日志会写清卡在哪一步 |
| 「换课」一直不动作 | 换课只在**目标课已确认有名额**之后才退保底课。目标课没名额就不会动你的保底课（这是故意的） |
| 提示音不响 | 浏览器要求先有用户交互才允许播声音，点过面板任意按钮后再抢就会有。想彻底关掉：取消勾选「抢到/被拒时响一声」 |
| 抢课中途自己停了，红字写「已连续失败 N 轮」 | 触发了连败熔断（你设了阈值）。先点「自检」看接口通不通、选课是否已开放，处理完再开始。设 0 可关闭熔断 |
| 想彻底卸载 | `chrome://extensions` → 移除。不会在教务系统留下任何东西；引擎内的账号密码（`storage.session` / `storage.local`）也随扩展一起删掉 |

> 排障小抄：F12 → Console → 左上角把 JavaScript 上下文切到本扩展，
> 敲 `__XK_HELPER__.pageState` 能看到当前判定结果（`select` / `other-zf` / `unknown`），
> 敲 `__XK_HELPER__.gotoSelectPage()` 可以手动跳一次，
> 敲 `__XK_HELPER__.params()` 能看到三个关键查询参数的值与**来源**（`dom` / `server` / `first*`），
> 敲 `__XK_HELPER__.harvest()` 可以手动跑一次服务器补参，
> 敲 `__XK_HELPER__.cred()` 能看到账号配置（回账号名与「是否已存密码」，**不含密码原文**），
> `__XK_HELPER__.checkSession()` 可以手动探一次登录态。
>
> v2.5.0 新增的几条：
> `__XK_HELPER__.parseSchedule('星期一第1-2节{1-16周}')` 看时间串能不能被拆开；
> `await __XK_HELPER__.conflictOf({sksj:'…'})` 列出与这门课时间重叠的已选课，并标出**哪门可退**；
> `__XK_HELPER__.isDroppable({kklxdm:'10',rwlx:'2'})` 自己验一下可退规则；
> `await __XK_HELPER__.dropCourse('<kch_id>','<do_jxb_id>')` 手动退一门课（**不可逆，慎用**）。
